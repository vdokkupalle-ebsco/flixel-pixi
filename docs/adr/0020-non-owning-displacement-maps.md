# ADR-0020: Non-owning normalized displacement maps

- Status: Accepted
- Date: 2026-08-11
- Accepted: 2026-08-11 (advanced-rendering checkpoint)

## Context

Pixi's built-in displacement filter uses a sprite to establish both the map
texture and its world transform. Introducing an invisible sprite per camera
would leak renderer-only nodes into logical containers and could interfere with
member ordering. Sharing one sprite between cameras would instead share mutable
renderer state.

The map texture also has a different lifetime from the filtered sprite. It may
come from an asset bundle, be shared by many effects, or be generated by the
game; a filter handle must not decide when that texture is destroyed.

## Decision

1. `FlxDisplacementFilter` holds a non-owning `FlxGraphic` reference. The game or
   asset service that supplied the map remains responsible for its lifetime.
2. The renderer samples the map in normalized filtered-object coordinates. It
   does not materialize or attach a hidden displacement sprite to the scene
   graph.
3. Red and green map channels control horizontal and vertical displacement.
   Scale is expressed in logical pixels; offset is expressed in normalized map
   coordinates. Maps repeat by default and may opt into clamping.
4. Scale and offset are revisioned runtime parameters. Each camera-local
   uniform group synchronizes changes without replacing the filter chain.
5. Each handle owns and destroys its Pixi filter and uniform group but never
   the map texture. Destroying a referenced map early produces a clear sync
   error instead of silently rendering from invalid GPU state.
6. Padding is fixed when the descriptor is created. Authors animating scale
   must reserve padding for the maximum intended displacement.

## Consequences

- Displacement behaves consistently for sprites and composites without adding
  renderer nodes or changing logical child order.
- One map can be cached and shared across objects and cameras without duplicate
  texture allocation.
- Mapping intentionally follows the filtered bounds rather than an independent
  world-space sprite. World-space heat haze or terrain fields can be authored
  as a custom shader when that coordinate model is required.
- The map must remain loaded until every referencing filter is removed or its
  owning object/camera is destroyed.
